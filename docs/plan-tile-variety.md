### 透明键（必须和窗口底色配套）

素材统一用 `(33,38,63)` 的洞底纯色当背景。这里有两件事必须**同时**成立，缺一个都会出问题：

1. 切分时把 `(33,38,63)` **全图集**键成透明
2. 游戏窗口底色 `Palette.BackgroundDark` 也设成 `(33,38,63)`

- 只有 2 没有 1：草丛、草角的洞里是实色，在背景上显出一块块比背景亮的方块
- 只有 1 没有 2：键掉的地方露出旧底色 `(18,21,32)`，地面只剩一条草带、岩石变漂浮碎斑
- 两个都有：没东西的地方露出的还是同色，视觉零变化；有背景层的格子里洞会透出被压暗的背景纹理

另外素材里还有第二个暗色 `(62,61,76)`（岩壁阴影），它同时是石砖的暗缝，
键掉会破坏墙体纹理，所以**保留不透明**。草角块内部因此会残留少量灰紫小块，属于可接受范围。

> 改底色前要注意：背景层是按 `BackdropBrightness = 0.5` 压暗绘制的，
> 所以有背景层的关卡里，前景的洞底若仍是实色，就会和压暗后的背景 (`≈16,19,31`) 打架。
> 这也是为什么透明键不能只对"装饰件"生效。

## 1. 现状诊断

### 1.1 重复感的主因是选取算法，不是变体不够

`Level.cs` 的 `TileDef.SpriteAt(x, y)`：

```csharp
int h = (x * 73856093) ^ (y * 19349663);
return Sprites[(h & 0x7fffffff) % Sprites.Length];
```

实测（15×10 区域，取模后）：

- `Sprites.Length == 4` → 完美的对角条纹 `0 1 2 3 0 1 2 3 …`
- `Sprites.Length == 2` → 完美棋盘格

两个乘数对 4 取模分别是 1 和 3，XOR 之后低两位仍保持线性关系，所以无论变体加到多少，画面都会出现规律纹路。

### 1.2 主力地形只挂了一个 sprite

| 关卡 | `g` 地面 | `=` 石墙 | `#` 岩体 |
|---|---|---|---|
| level1 | `[9]` | `[11]` | `[0,1,2,26]` |
| level2 | `[9]` | `[11]` | `[0,1,2,26]` |
| classic-1 | `[9]` | — | `[0,1,2,26]` |
| bg-test | `[9]` | `[11]` | — |

整条地面、整面墙完全一样，是最直观的重复来源。

### 1.3 图例里混装了不同「角色」的瓦片

| 字符 | 现有 sprites | 问题 |
|---|---|---|
| `#` 岩体 | `0, 1, 2, 26` | **26 是草块**（绿色），混进暗岩里会随机冒出草 |
| `m` 灰石砌墙 | `30, 33, 34` | 30 是「竖条 + 棕块」，33/34 是灰色大砖，**跨材质** |
| `L` 梯子 | `65` | 65 是**蓝白竖条纹的水流**，真正的木梯是 `54` |
| `r` 碎石墙 | `32, 47, 4` | 4 是暗底斑点，47 是横梁 |

> 术语说明：本文的「岩体」指编辑器预设里字符 `#` 对应的名字，即四张地图里大片填充的暗蓝色岩石（sprite `0,1,2,26`）。它是**无方向纹理**，没有边框，因此不套九宫格。

## 3. 设计（最终方案：逐格变换）

素材不是九宫格，只有边角/中心几个独立变体，方向差异由使用者手动补。
所以不做"按邻居自动选片"，改成**每格自己记住精灵和朝向**，运行时纯查表。

### 3.1 格子模型：一格一图 + 两个标志

每个格子只存**一张图**，另外带两个独立布尔：

| 字段 | 含义 |
|---|---|
| `rows` | 这一格用哪个图例字符 |
| `var` | 用该图例 `sprites` 里的第几个（可选） |
| `xf` | 朝向（可选） |
| `solid` | 是否阻挡：`'1'` 挡、`'0'` 可穿过、`'.'` 跟随瓦片默认 |
| `dim` | 是否压暗绘制：`'1'` 压暗、`'.'` 正常亮度 |

**为什么要拆出 `solid`**：原来"挡不挡"是瓦片的属性，导致"前景层里的装饰瓦片不挡人"这种
不整齐的规则，也没法让同一块瓦片在某格挡、另一格不挡。现在控制权在格子上，
瓦片只提供默认值。

**`dim` 取代了原来的"背景层"**：以前背景是一整层、整层统一压暗；现在压不压暗是逐格的事，
所以"暗色远景"可以是零星几格，也可以和阻挡自由组合（挡住 + 压暗 = 远景里的暗墙）。

```json
"pieces": [{
  "rows": ["....##"],
  "var":  ["..0..."],
  "xf":   ["....2."],
  "solid":["....10"],
  "dim":  ["....11"]
}]
```

各层全空时不写进 JSON，旧关卡一个字节都不变。

### 3.2 朝向编码

| 值 | 含义 |
|---|---|
| 0 | 原样 |
| 1 / 2 / 3 | 顺时针 90° / 180° / 270° |
| 4 | 水平镜像 |
| 5 / 6 / 7 | 水平镜像 + 90° / 180° / 270° |

渲染时先镜像再旋转。`6` 恰好等价于垂直镜像。

### 3.3 编辑器交互

- 右侧整张图集点选，点任意格都能画（没有对应图例条目时自动新建一条单精灵图例）
- 左侧「画笔标记」：一个下拉选阻挡（跟随瓦片 / 总是挡 / 可穿过），一个勾选框选变暗
- 快捷键：`H` / `V` / `R` 翻转旋转，`S` 循环阻挡，`D` 切换变暗；
  都同时作用于画笔和光标下那一格
- 画布右下角小点标出阻挡状态：白点 = 挡、红点 = 被覆盖成可穿过、半透明点 = 跟随瓦片且默认挡
- 状态栏显示当前画笔的变体、朝向、阻挡与变暗状态

### 3.4 兼容性

- 旧 JSON 无 `var` / `xf` / `solid` / `dim` → 全部走老逻辑，渲染结果与改动前一致
- 旧格式的 `back` 层会在加载时合并：back 有内容而前景为空的格子，
  把图搬进 `rows` 并标 `dim=1`；两层都有内容时保留前景（背景那层会丢）
- 编辑器保存后一律输出新的单层格式，`back` 不再写出

## 8. 构建与启动

一键脚本（双击即可）：

- `build.cmd` —— 打包素材 + 编译游戏与编辑器
- `play.cmd 关卡名` —— 先关掉旧进程再按名字启动；不带参数会列出当前可用关卡

### 资源复制为什么不用 MSBuild 的 Copy 任务

本机上 `Copy` 任务的 `ParallelCopyTask` 只要遇到「删除目标位置的旧文件」就栈溢出（exit 127），
`-m:1` 压不住，清 `bin`/`obj` 只能绕开那一次。

现在改成 `CopyGameAssets` 目标（`AfterTargets="Build"`）用 `xcopy /Y /D` 直接覆盖，
不先删文件，稳定通过。素材源目录 `assets/tiles/` 和备份 `tiles-original.png` 不参与复制。

### 三个容易踩的坑

1. **编辑器开着时打包会失败**。编辑器用 `new Bitmap(tiles.png)` 打开图集，句柄一直不释放，
   Windows 下连替换都不允许。打包脚本现在会明确提示「tiles.png 被占用」，关掉编辑器重试即可。
2. **批处理必须是 CRLF**。写成 LF-only 的 `.cmd`，cmd.exe 解析会出岔子（行尾被当成命令的一部分）。
   写完用字节检查确认 `\r\n`。
3. **不要随手跑 `--split`**：它会从 `tiles-original.png` 重切、覆盖 `assets/tiles/` 下的单文件。
   只想更新图集时用 `--pack`（`build.cmd` 调的就是默认的「切分 + 打包」）。
